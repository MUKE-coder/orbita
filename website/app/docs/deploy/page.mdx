# Deploy an app

Orbita deploys **any containerisable app**: a Docker image, a Compose file, a repo with a
Dockerfile, or a repo with nothing at all (Nixpacks figures it out). You can do all of it from
the dashboard — the CLI is optional.

<Callout type="tip" title="No framework required">
Laravel, Django, Rails, Next.js, Go, a static HTML site — all first-class. If you happen to use
Grit, see [Deploying Grit apps](/docs/grit-apps) for the zero-config path.
</Callout>

## Docker image

```text title="Orbita dashboard"
Apps → Create App → Source: Docker Image
  Image: nginx:alpine
  Port:  80
→ Deploy
```

Private registry? Add credentials under **Settings → Registries** first.

## Git repository

Connect GitHub once:

```text title="Orbita dashboard"
Settings → Git Connections → add a token
  Scopes: repo + admin:repo_hook
```

Then:

```text title="Orbita dashboard"
Apps → Create App → Source: Git Repository
  Pick the repo + branch
  Build: Dockerfile          ← used automatically when your repo has one
→ Deploy
```

Orbita registers a webhook, so **every push to that branch redeploys**.

## Nixpacks (any language)

No Dockerfile? Pick **Nixpacks** as the build method and Orbita detects the language from your
repo and builds a production image — Laravel, Django, Rails, Node, Go, static sites.

```text title="Orbita dashboard"
Apps → Create App → Source: Git Repository
  Pick the repo + branch
  Build: Nixpacks
→ Deploy
```

<Callout type="note" title="Nixpacks vs a Dockerfile">
If your repo has a `Dockerfile`, prefer it — it's explicit and reproducible. Nixpacks exists so
apps **without** one still deploy with zero config.
</Callout>

## Docker Compose

```text title="Orbita dashboard"
Apps → Create App → Source: Docker Compose
  Paste or point at your compose file
→ Deploy
```

## Add a database

Orbita provisions managed addons into your organisation's isolated network and injects the
connection URLs into your app's environment:

```text title="Orbita dashboard"
App → Addons → Add
  Postgres  → injects DATABASE_URL
  Redis     → injects REDIS_URL
  MinIO     → injects STORAGE_DRIVER + MINIO_*
```

Nothing is exposed publicly — addons are reachable only from inside the org network.

## Domains and HTTPS

```text title="Orbita dashboard"
App → Domains → Add
  shop.example.com
```

Point an **A record** at your server first. Traefik requests a Let's Encrypt certificate on the
first request — if the certificate never issues, DNS or the firewall is the usual cause; see
[Troubleshooting](/docs/troubleshooting).

## Environment variables

```text title="Orbita dashboard"
App → Environment → Add / Import .env
```

Values are encrypted at rest with a key derived per organisation. Mark a variable as a **secret**
and it's write-only — visible to the container, never re-displayed in the UI.

## Roll back

```text title="Orbita dashboard"
App → Deployments → pick a previous deploy → Rollback
```

Previous images are retained, so rollback is an image swap, not a rebuild.

## Doing it from the terminal instead

Optional. With the [CLI](/docs/cli) and an [`orbita.yaml`](/docs/orbita-yaml) in your project:

```bash title="Local terminal (your PC)"
orbita deploy --plan --host prod    # preview — changes nothing
orbita deploy --host prod
orbita logs -f --host prod
orbita rollback --host prod
```
