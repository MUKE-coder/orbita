# Before you begin

Three things to have ready before you install Orbita: **a server**, **a domain** (optional but
recommended), and **an SSH key** (optional). This page walks a first-timer through each one. If
you already have them, skip to the [Quickstart](/docs/quickstart).

<Callout type="tip" title="Nothing here is Orbita-specific">
A server, a domain, and an SSH key are the same three things every self-hosted tool needs
(Coolify, Dokploy, Vercel-on-your-own-box). Set them up once and you're ready for anything.
</Callout>

## 1. Get a server

Orbita runs on a **VPS** — a small Linux server you rent by the month. You need:

- **Ubuntu 22.04 or 24.04** (a fresh one — don't reuse a box that already serves sites)
- **2 GB RAM minimum**, 4 GB recommended (builds are the hungry part)
- **30 GB+ disk**, a public IP, and root access

### Where to get one

Any of these work. Prices are roughly $4–7/month for a 2 GB box.

  </Card>

When you create the server:

1. Choose **Ubuntu 24.04 (LTS)** as the image.
2. Pick a plan with **at least 2 GB RAM**.
3. If asked "SSH key or password?" — either is fine. If you add an SSH key now (see
   [step 3](#3-create-an-ssh-key-optional)), you won't need the password.

<Callout type="danger" title="Write these three down — you need them for install">
As soon as the server is created, save:

- **The server's IP address** (e.g. `203.0.113.10`)
- **The root password** (if the provider gave you one), or
- **The SSH key** you used to create it

Keep them somewhere safe. You'll paste the IP into the very first install command.
</Callout>

## 2. Get a domain

Optional, but without one you get `http://YOUR_IP:8080` (no HTTPS). With a domain you get real
**HTTPS certificates** for free, automatically.

### Buy one

<Cards>
  <Card title="Cloudflare" badge="Recommended" icon="browser">
    Domains at cost, and the easiest DNS to manage. Also gives you free DDoS protection.
  </Card>
  <Card title="Namecheap / Porkbun" icon="browser">
    Cheap domains with simple DNS panels. Any registrar works.
  </Card>
</Cards>

### Point it at your server

You control Orbita on **one** subdomain, and each app you deploy gets its **own** subdomain.
Create an **A record** for each, all pointing at your server's IP:

| Subdomain | For | Example |
|---|---|---|
| `orbita.` | The Orbita dashboard | `orbita.example.com` |
| your app | An app's website | `shop.example.com` |
| `api.` | That app's API (if it has one) | `api.shop.example.com` |
| `admin.` | That app's admin panel (if it has one) | `admin.shop.example.com` |

In your registrar's DNS panel, that's:

```text title="DNS records (at your registrar)"
Type   Name              Value            Proxy
A      orbita            203.0.113.10     DNS only
A      shop              203.0.113.10     DNS only
A      api.shop          203.0.113.10     DNS only
A      admin.shop        203.0.113.10     DNS only
```

<Callout type="warning" title="Cloudflare users: turn the proxy OFF (grey cloud)">
Set each record to **DNS only** (grey cloud), not Proxied (orange). Orbita's Traefik gets the
Let's Encrypt certificate itself; the orange-cloud proxy gets in the way of that first handshake.
You can turn it on later once HTTPS works.
</Callout>

<Callout type="tip" title="Or use a wildcard">
One `A` record for `*` (`*.example.com → your IP`) covers every subdomain at once, so you don't
edit DNS for each new app. Handy if you'll deploy a lot of apps.
</Callout>

### Check it worked

DNS can take a few minutes to an hour. Confirm it resolves to your server **before** you install —
Let's Encrypt can't issue a certificate until it does:

```bash title="Local terminal (your PC)"
dig orbita.example.com +short
```

It must print your server's IP.

## 3. Create an SSH key (optional)

An SSH key is a passwordless, far-more-secure way to log into your server. Orbita's hardening step
can **generate one for you** if you skip this — so it's genuinely optional. But making your own is
quick:

<Cards>
  <Card title="I already have one" badge="Skip ahead" icon="key">
    If `cat ~/.ssh/id_ed25519.pub` prints a line starting with `ssh-ed25519`, you're set — that's
    your public key.
  </Card>
  <Card title="I don't have one" icon="key">
    Make one now with the command below. Takes five seconds.
  </Card>
</Cards>

```bash title="Local terminal (your PC)"
ssh-keygen -t ed25519 -C "you@example.com"
```

Press Enter through the prompts (a passphrase is optional). This creates two files:

- `~/.ssh/id_ed25519` — your **private** key. **Never share it.** It's your identity.
- `~/.ssh/id_ed25519.pub` — your **public** key. Safe to paste anywhere; this is what goes on servers.

<Callout type="danger" title="The private key is the one that matters">
Anyone with your private key can log into your servers. Never paste it into a website, a chat, or
a config file. When a step asks for "your key", it means the **`.pub`** (public) one.
</Callout>
