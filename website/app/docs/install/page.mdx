# Set up your server

Two things have to happen before you deploy anything: **harden the server**, then **install
Orbita**. This page does both, in that order.

<Callout type="tip" title="No Grit, no Go, no clone required">
Orbita is a standalone PaaS. Nothing here needs the Grit framework. The `orbita` CLI is
**optional** — like the Vercel CLI, it's a convenience, not a requirement. Pick a path below.
</Callout>

## Pick your path

<Tabs labels={["One command (with the CLI)", "Manual (no CLI)"]}>
<TabItem>

The CLI does the whole job from your own machine — hardens the box, installs Orbita, creates
your admin login, and registers the host:

```bash title="Local terminal (your PC)"
orbita init
```

It's an interactive wizard: it asks for the IP, how you log in today, a deploy user name, and a
domain (blank = use the IP). [Install the CLI first](/docs/cli#install) if you don't have it,
or use the manual path instead — the result is the same.

Skip to [Step 3](#step-3--create-your-admin-account) once it finishes.

</TabItem>
<TabItem>

Two scripts, run on the server, in order. That's **Step 1** and **Step 2** below.

No CLI, no Go — just SSH and `curl`.

</TabItem>
</Tabs>

## What you need

- A **fresh Ubuntu 22.04 or 24.04 VPS** with a public IP, and **root** access.
- **2 GB RAM minimum**, 4 GB recommended (builds are the hungry part).
- Ports **80**, **443** and **8080** free.
- Optional: a domain, if you want HTTPS instead of a bare IP.

Don't have these yet, or new to self-hosting? [**Before you begin**](/docs/before-you-begin) shows
you how to get a server, point a domain at it, and make an SSH key — start there.

<Callout type="danger" title="Use a fresh box">
Orbita's Traefik must own ports 80/443. If `nginx`, `apache2`, `caddy` or `lighttpd` holds one,
the installer **stops and uninstalls it** — and with `--yes` it does so **without asking**. Don't
run this on a server that already serves sites.
</Callout>

### Point DNS first (skip for IP mode)

Only if you want HTTPS. Create an **A record** for your dashboard hostname pointing at the
server's IP, and confirm it resolves **before** installing — Let's Encrypt can't issue a
certificate until it does:

```bash title="Local terminal (your PC)"
dig orbita.example.com +short
```

It must print your server's IP. No domain yet? Use IP mode; Orbita installs on
`http://YOUR_IP:8080` and you can add a domain later.

## Step 1 — Harden the server

Log in as root:

```bash title="Local terminal (your PC)"
ssh root@YOUR_SERVER_IP
```

<Callout type="warning" title="Steps 1 and 2 run on the server">
Everything below runs **inside that SSH session** — look for the amber “Server terminal” label.
</Callout>

Download the hardening script and read it before running it (it changes how you log in):

```bash title="Server terminal (SSH)"
curl -sSL https://raw.githubusercontent.com/MUKE-coder/vps-harden/main/vps-harden.sh -o vps-harden.sh
chmod +x vps-harden.sh
less vps-harden.sh
```

Run it interactively — it will ask for a deploy user and your public key:

```bash title="Server terminal (SSH)"
sudo ./vps-harden.sh --no-dokploy
```

<Callout type="danger" title="This locks down root SSH — don't get locked out">
The script creates a sudo user, installs your public key, then **disables root login and
password auth**. Before you disconnect, open a *second* terminal and confirm
`ssh deploy@YOUR_SERVER_IP` works. If you have no key, let the script generate one and save it
— it prints the path.
</Callout>

`--no-dokploy` matters: the script can install Dokploy, and **Orbita replaces Dokploy**. Never
install both — they both want ports 80/443.

To script it instead of answering prompts:

```bash title="Server terminal (SSH)"
sudo NEW_USER=deploy SSH_PUBKEY="ssh-ed25519 AAAA... you@laptop" \
  ./vps-harden.sh --no-dokploy --yes
```

What it does: creates the sudo user with **passwordless sudo** and your key, disables root +
password SSH, enables **UFW + ufw-docker** (so container ports don't bypass the firewall) and
Fail2ban, applies kernel hardening, and prints a **0–100 security score**.

<Callout type="tip" title="Optional: move SSH off port 22">
Add `--auto-port` (or set `SSH_PORT=2222`) to move SSH to a non-default port — it's printed
loudly and opened in UFW. Left off by default, because some providers filter non-standard ports
at their own edge and you'd be locked out. If you use it, connect with `ssh -p <port> …` after.
</Callout>

Just want the score without changing anything?

```bash title="Server terminal (SSH)"
sudo ./vps-harden.sh --audit-only
```

## Step 2 — Install Orbita

The installer brings its own **Docker, Swarm, Postgres, Redis and Traefik** — install nothing
first.

<Tabs labels={["With a domain (HTTPS)", "IP mode (no domain)"]}>
<TabItem>

```bash title="Server terminal (SSH)"
curl -sSL https://raw.githubusercontent.com/MUKE-coder/orbita/main/install.sh \
  | sudo ORBITA_DOMAIN=orbita.example.com ORBITA_ACME_EMAIL=you@example.com bash -s -- --yes
```

Traefik requests a Let's Encrypt certificate on the first request to your domain.

</TabItem>
<TabItem>

```bash title="Server terminal (SSH)"
curl -sSL https://raw.githubusercontent.com/MUKE-coder/orbita/main/install.sh \
  | sudo bash -s -- --yes
```

Orbita comes up on `http://YOUR_SERVER_IP:8080`, no TLS. Add a domain later for HTTPS.

</TabItem>
</Tabs>

<Callout type="tip" title="The firewall is handled for you">
Hardening installs `ufw-docker`, which **firewalls every published container port by default** —
a real security win (without it, Docker publishes ports straight past UFW). The installer then
opens exactly what Orbita needs (80 + 443 in domain mode, 8080 in IP mode) with the right
`ufw route allow` rules. You don't run any `ufw` commands yourself — a plain `ufw allow` wouldn't
even work for a container port under ufw-docker.
</Callout>

### What the installer does, in order

1. Installs **Docker** if missing and enables the daemon.
2. Initialises **Docker Swarm** if it isn't active.
3. Checks ports **80 / 443 / 8080** are free (see the warning above).
4. Generates secrets, writes `/opt/orbita/.env` and `/opt/orbita/docker-compose.yml`.
5. Pulls `ghcr.io/muke-coder/orbita:latest`.
6. Starts **Orbita + PostgreSQL + Redis + Traefik**.
7. Opens its ports through the firewall (`ufw route allow`), waits up to **2 minutes** for
   `/health` to report ok, then prints the dashboard URL.

<Callout type="danger" title="Back up /opt/orbita/.env">
It holds `ENCRYPTION_MASTER_KEY`. Every organisation's encryption key is derived from it —
**lose that file and every stored secret is unrecoverable.** Copy it somewhere safe before you
put real data in.
</Callout>

### Verify it's up

```bash title="Server terminal (SSH)"
curl -s http://localhost:8080/health
cd /opt/orbita && sudo docker compose ps
```

Expect `{"status":"ok", ...}` and `orbita`, `orbita-postgres`, `orbita-redis`, `orbita-traefik`
all **Up**. (The `deploy` user reaches Docker through `sudo` — it's deliberately **not** in the
`docker` group, since that group is root-equivalent.) Then confirm it answers from outside — on
your own machine:

```bash title="Local terminal (your PC)"
curl -I https://orbita.example.com
```

## Step 3 — Create your admin account

Open the dashboard:

- **Domain mode:** `https://orbita.example.com`
- **IP mode:** `http://YOUR_SERVER_IP:8080`

**Register the first user** — that account becomes the super-admin. Do it immediately:
registration is open until the first account exists. Then create your first organisation.

Done. [Deploy an app](/docs/deploy) — the dashboard is enough; no CLI required.

## Managing the install

<Tabs labels={["Update", "Back up", "Stop", "Full reset"]}>
<TabItem>

```bash title="Server terminal (SSH)"
cd /opt/orbita
sudo docker compose pull orbita
sudo docker compose up -d orbita
```

Migrations run automatically on startup.

</TabItem>
<TabItem>

```bash title="Server terminal (SSH)"
sudo docker exec orbita-postgres pg_dump -U orbita orbita | gzip > orbita-$(date +%F).sql.gz
sudo cp /opt/orbita/.env orbita-env-$(date +%F).backup
```

Back up **both** — the dump is useless without the key in `.env`.

</TabItem>
<TabItem>

```bash title="Server terminal (SSH)"
cd /opt/orbita && sudo docker compose down
```

Stops everything; data volumes are kept.

</TabItem>
<TabItem>

```bash title="Server terminal (SSH)"
curl -sSL https://raw.githubusercontent.com/MUKE-coder/orbita/main/install.sh \
  | sudo bash -s -- --force-reset --yes
```

**Destroys all data** — containers, volumes, database, and `.env`.

</TabItem>
</Tabs>
